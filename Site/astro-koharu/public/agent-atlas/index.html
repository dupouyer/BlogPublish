05 / RESEARCH PROTOCOL

证据、评分与历史阅读规则

用时间切片防止“现在看起来必然”的后见之明。阅读事件时，请区分发布声明、案例结果与编者推论。

三层证据，不混为一谈

  • 发布事实：具体产品/论文在何时公开、声称和演示了什么。
  • 当时约束：当期公开记录中提到的失败模式、成本和不确定性。
  • 2026 复盘：后续文章、工程案例或独立测量如何改变对路线的判断。

“选中路线”不等于科技史上的唯一正确答案；多 Agent 与单 Agent、GUI 与 API、短会话与持久工作流长期并存。

能力 0—5 分的含义

1—2 · 局部可用可完成低风险短任务，失败需人类及时纠偏。
3 · 项目级实用能完成真实仓库任务，但仍有明显上下文和可靠性瓶颈。
4—5 · 前沿实验/成熟系统在良好工具、沙箱和验证条件下可长期执行，不代表普适无错。

这是一组定性编辑评分，用于观察生态整体方向；评分的变化不表示精确增益，更不等于 METR 时间跨度或 SWE-bench 通过率。后者在其原始方法下独立阅读。

不可避免的史料局限

公开发布记录会夸大成功案例的可见度。某些策略其实同期并存，没有“官方淘汰”结论。我们将路线结果标为编者归纳，并保留具体案例、使用条件和反例。历史模式隐藏后期发表的成果，不把未出现的知识倒灌回过去。

独立量化指标去哪里看？

METR Task-Completion Time Horizons ↗ 以任务的人类耗时与可靠性建立长程能力刻度。
Anthropic Evals 指南 ↗ 解释 pass@k 和 pass^k 的区别。
OpenAI Harness Engineering ↗ 展示从模型能力到可交付生产系统所需的验证层。

企业内部报告与供应商 benchmark 不应直接视为独立可复现实验。

# 可理解、可下钻、可审查的博客

## 联合设计三层

将 STE 的少歧义语言、软件工程的可审查结构与 Karpathy 的视觉/动态呈现作为共同工作的视角；这是综合方法，不把三者误称为互不相关或作者共同制定的标准。中文借用 STE 原则，不宣称完整标准合规。核验作者原话；我们的建议明确标为延伸。

首屏说明文章问题、核心判断和成立条件，给读者整体模型；正文按关键问题下钻到输入、状态、转换、输出和证据，再回看局部改变对整体的影响。观点类下钻到论据和反例，源码类映射到符号与版本，算法类映射到公式、读写状态和边界；不强套软件模块。

每个核心小节要有定位入口（标题/图中标签/代码符号），读者无需重读整篇即可找到讨论对象。自描述至少包含范围、术语、图例/单位/箭头含义、假设、证据状态与未知项。代码无法表达的设计原因保留短说明。

## 语言与阅读组织

- 同一对象使用同一名称；主语、动作、条件和结果明确，减少模糊代词和“灵活支持”等空泛概念。保留改变判断的条件，不能为缩短句子而删掉它们。
- 并列事项/步骤优先列表，比较与变量映射用表格，因果推导用连贯短段。真实顺序才编号；不可审查的长文切成很多条仍不可审查。
- 图文、公式、代码与交互表达同一模型；来源事实、推断、建议、示例和实测可辨认，证据对应当前版本。不要把说明性演示当真实引擎验证或性能测量。

## 主动制作图形与动态演示

复杂关系主动制作图，空间或时间演化主动考虑动画、交互和短视频；不能总以“按需”退回纯文字，或只给读者一个建议。媒介要帮助定位和观察决定结果的变化。图先显示关键关系，局部图再与公式/代码对应，不能只放概念方框。

| 目标 | 可制作的形式 |
| --- | --- |
| 系统边界、责任和依赖 | 关系图 + 局部定位 |
| 数据读取、转换和写回 | 数据流图 + 字段/代码映射 |
| 状态/算法演化 | 可暂停的短动画/视频 + 关键帧 |
| 参数与反例 | 可控交互，允许改变相关条件 |
| 论据与方案取舍 | 带来源和条件的表格/图表 |

先定义学习目标、输入/控制、观察量、规则、边界和预期结果，再制作。显示关键中间状态；让读者能暂停、重放或步进，按演示需要选控件。保留静态后备、可读代码/步骤与简化假设。视频帮助建立过程直觉，交互帮助停在局部检查；无需每篇同时使用所有媒介。

封面使用合适的生成插画或已有资源；精确工程图与公式采用可控绘图/代码。重要原图按既有许可和出处规则使用，不因原创演示而省略必要原文证据。受阻时说明实际缺项，不虚构视频或图片。

## 从局部回看整体

正文局部结论写明成立条件与依据，指出哪些整体判断已能确认、哪些仍未知。算法例子核验后，只能证明例子与规则一致，不能保证真实实现的并发、资源生命周期或性能。图看懂与设计正确、实现验证是不同状态。

长篇文章让读者能建立整体模型、下钻一处、追到依据、回看影响。五到十分钟理解总览、十秒理解一个局部可作为设计目标，不承诺效率倍数。延伸仅纳入会改变主判断的内容，其他作为短入口，不随检索结果无限扩写。

## 验收

读者能否定位关键关系？能否预测一个输入变化？能否找到依据和假设？能否发现反例/失效条件？能否从局部结论回到主问题？检查源码和动态结果一致、静态后备可读、手机图文/控件不溢出。明确实际执行的检查；未运行、未部署和未核验网页不能写成已完成。

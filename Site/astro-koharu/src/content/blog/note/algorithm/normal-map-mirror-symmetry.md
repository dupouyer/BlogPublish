把两个 Quad 并排放置，一个 `ScaleX=+1`，另一个 `ScaleX=-1`，给它们使用同一张切线空间法线贴图。居中的球形凸起看起来一样，方向测试图和卷草浮雕却变了。这个现象很容易让人怀疑：负缩放是否破坏了法线？是否必须把材质切到世界空间？

**法线贴图可以用于镜像模型。关键在于：镜像后的浮雕是否满足你要比较的对称条件，以及采样坐标与法线基底是否对应。** 对严格左右对称的高度场，正确镜像后的世界法线可以在同一归一化位置保持一致；普通花纹没有这个保证。若需求是只镜像模型、保持材质朝向，则要同时处理采样位置和法线方向。

针对不规整的 AI 法线，还容易提出“UV 镜像，但法线世界方向不镜像”的目标。**只保留镜像采样、再取消方向反射，会改变它所表达的坡度，不能当作源贴图的通用修复。** 本文保留这个实验作为反例：实现先使用与 UV 对应的真实基底；资产问题单独检查；若颜色需要镜像而法线保持原朝向，则明确分离两条采样链路及其代价。

本文以 UE5.3/5.4 的材质工作流为应用语境，先推导正交平面的最小模型，再讨论自定义投射。下文交互与 Python 检查验证的是数学模型；HLSL 是接入示例，未在 UE 工程、Nanite、ISM 或移动渲染路径中运行。官方在线文档可能跳转到较新版本，因此不据此承诺所有版本和渲染路径的负缩放行为一致。

## 先约定：比较的是哪两个位置

两个平面分别居中，把平移差去掉以后，取相同的横向归一化位置 $x\in[0,1]$。原平面的该位置采样 $u=x$；模型水平镜像后，该位置对应原模型另一侧，采样 $u'=1-x$。

这句话描述的是**世界位置到模型 UV 的对应关系**。模型上的顶点 UV 属性并没有被引擎统一改写成 `1-UV.x`。如果追踪同一个模型顶点，它仍携带原来的 UV，只是移动到了另一侧。

![同一归一化位置在原 Quad 上采样 U=x，在负缩放 Quad 上采样 U=1-x；切线 T 同时反向](/img/posts/normal-map-mirror-symmetry/basis.svg)

图 1：镜像同时改变“这里取哪一个像素”和“像素里的方向怎样转到世界”。本文原创示意；假设模型 X 与 UV 的 U 方向对齐，镜像轴通过平面中心。

后面的 $T$、$B$、$N$ 分别是原平面的单位切线、副切线和几何法线。在这个特定平面上，镜像轴沿 $T$，法线垂直于镜像轴，所以：

$$
T'=-T,\qquad B'=B,\qquad N'=N.
$$

**模型 X 轴不必等于 UV 的 U 轴。** UV 旋转、斜切、不同面朝向或另一根镜像轴都会改变这组关系。不能把本文的 `NormalTS.x *= -1` 无条件套到任意模型。

## 一个像素存的是相对于基底的方向

切线空间法线 $n=(n_x,n_y,n_z)$ 的三个分量对应 $T,B,N$。在正交单位基底下，世界空间着色法线为：

$$
N_w(u,v)=\operatorname{normalize}\big(n_x(u,v)T+n_y(u,v)B+n_z(u,v)N\big).
$$

这里要分清三个对象：

| 对象 | 用途 | 是否随贴图变化 |
| --- | --- | --- |
| 几何法线 $N$ | 定义表面朝向及基底 | 最小平面模型中不变 |
| 切线法线 $n$ | 贴图在自己的坐标系中表达的方向 | 随采样位置变化 |
| 世界着色法线 $N_w$ | 最终参与光照的方向 | 由采样与基底共同决定 |

用普通 RGB 保存标准法线时，示意编码是 $C=0.5n+0.5$；解码是 $n=2C-1$。但 UE 的 Normal 类型采样已经处理了法线解码，不能再对它无条件执行一次 `*2-1`。GPU 上的压缩格式也可能只保存 XY，再重建 Z，因此文件里的蓝通道不一定是运行时参与计算的那份数据。

[MikkTSpace 的接口说明](https://github.com/mmikk/MikkTSpace/blob/master/mikktspace.h)给出了切线与手性符号的组合关系：

```hlsl
B = Handedness * cross(N, T);
```

`Handedness` 是相应基底的 ±1 符号。网格切线数据中的手性与物体变换造成的朝向变化，需要由实际渲染管线一致处理。只写 `B=cross(N,T)`，相当于固定选择一种手性；当本例的 $T$ 反向时，就会把本应保持的 $B$ 也翻掉。镜像 UV 与负物体缩放是不同操作，不能混用它们的标志。

Epic 的 [Transform 材质表达式文档](https://dev.epicgames.com/documentation/en-us/unreal-engine/vector-operation-material-expressions-in-unreal-engine#transform)明确说明它考虑镜像 UV。但这不等于一条涵盖所有负缩放、实例化和自定义基底的验证结论。具体项目仍要检查最终世界法线。

## 球形凸起为什么能抵消两次变化

在本文的平面条件下，镜像平面最终得到：

$$
N'_w(x,v)=\operatorname{normalize}\big(-n_x(1-x,v)T+n_y(1-x,v)B+n_z(1-x,v)N\big).
$$

要在同一位置满足 $N'_w(x,v)=N_w(x,v)$，对于单位法线场就需要：

$$
\begin{aligned}
n_x(1-u,v)&=-n_x(u,v),\\
n_y(1-u,v)&=n_y(u,v),\\
n_z(1-u,v)&=n_z(u,v).
\end{aligned}
$$

居中的标准球形凸起满足这组关系：左侧与右侧的横向斜率大小相等、方向相反，另两个分量相同。镜像后的采样先取得另一侧的 $n_x$，切线 $T$ 再反向，最终方向抵消。

例如原位置的法线是 $(0.6,0.2,\sqrt{0.6})$，镜像位置恰好是 $(-0.6,0.2,\sqrt{0.6})$；后者乘上 $(-T,B,N)$，就得到相同世界法线。这里的 Z 约为 0.775，两者都是单位向量。

这是一种特殊的对称性。**球形测试成功，只说明该样例的变化能够抵消；不能单独证明非对称贴图、另一套 UV 或自定义基底也正确。** 绿色通道被错误翻转时，球形的明暗和凸凹判断同样可能改变，不能因为轮廓仍然圆就说 Green 约定无关。

## 浮雕要对称，导数也必须对称

对平面上的单值高度场，采用等尺度参数，并把 $n_y$ 定义为沿 V 增长方向的分量：

$$
n(u,v)=\operatorname{normalize}\left(-\frac{\partial H}{\partial u},-\frac{\partial H}{\partial v},1\right).
$$

若高度场满足严格左右对称：

$$
H(1-u,v)=H(u,v),
$$

对两边求导，链式法则给出：

$$
H_u(1-u,v)=-H_u(u,v),\qquad H_v(1-u,v)=H_v(u,v).
$$

两个位置的坡度长度相同，所以归一化以后仍然满足前面的法线对称条件。图案整体均衡、轮廓近似对称、叶片数量相同，都不能替代这个导数条件：细小的沟槽、方向性细节和不同旋向的卷曲，都可能改变局部坡度。

还有一个容易漏掉的条件：**对称轴必须与正在执行的镜像映射一致。** 一个重复铺排的纹样可能围绕某个单元中心对称，却不围绕整张贴图的 `u=0.5` 对称。UV 平移、平铺倍率或裁剪窗口会改变对应关系；此时需要检查实际映射 $u\mapsto c-u$，而不是仅比较原图的左右边。

### 四象限图测的是方向，不能要求它镜像后相同

一种方向测试图的布局是：

| | 左侧 | 右侧 |
| --- | --- | --- |
| 上半部 | $+U$ 倾斜 | $-U$ 倾斜 |
| 下半部 | $+V$ 倾斜 | $-V$ 倾斜 |

上半部可能抵消 X 镜像；下半部的 Ny 左右反号，明确违反 $n_y(1-u)=n_y(u)$，因此世界法线应当改变。它是一张方向诊断图，未必能积分成连续的真实高度场。不能只凭“不一样”就判定手性错误；应把各象限预测的世界方向与实际 GBuffer 比较。

## 镜像几何并不意味着明暗图也镜像

这是从“法线正确”走到“光照正确”时最关键的边界。令 $R=\operatorname{diag}(-1,1,1)$，在 T/B/N 对齐的坐标中，镜像后的法线场为 $R\,N_w(1-x,v)$。

简化 Lambert 光照是：

$$
I(x,v)=\max\big(0,N_w(x,v)\cdot L\big).
$$

固定世界光源时，镜像版本得到：

$$
I'(x,v)=\max\big(0,N_w(1-x,v)\cdot R L\big).
$$

这通常不等于 $I(1-x,v)$。同一片斜坡从朝向左灯变成背向左灯，几何做了镜像，亮度却不能直接拿原图左右翻转得到。若光源也变成 $L'=RL$，这个简化模型中的亮度才会与原图构成镜像。

反过来，两个不同的法线也可能具有相同的 `dot(N,L)`。例如只有 X 分量反号、而 $L_x=0$ 时，漫反射亮度可以相同。黑区的 `max(0,·)` 截断还会掩盖更多差异。**单个光源的颜色截图不足以证明法线场一致；世界法线视图更直接。**

即使两块平面的世界法线相同，真实场景中的点光源方向、视线、高光、阴影、AO、反射和曝光差异仍可能让颜色不同。交互故意同时给出“法线角差”和“亮度差”，避免把两个量混成一个结论。

前面已经解释了“为什么会不同”。接下来把这个判断用于材质制作：**先确定你希望浮雕怎样变化，再选择实现，最后检查它是否达到了那个目标。**

## 先确定目标：图案位置和法线方向分别怎样镜像

同样是两扇左右镜像的门，要分别决定两件事：花纹采样位置是否交换，采样到的方向是否反射。前两种目标可以分别对应“真实浮雕一起镜像”和“材质整体保持朝向”。第三种操作只交换位置、取消方向反射，会与镜像高度的坡度不一致，必须看清它改变了什么。

以下表格沿用对齐 Quad，原位置采样 $n(x,v)$；右侧网格基底是 $(-T,B,N)$。省略单位基底下不改变方向的归一化。

| 目标 | 右侧采样位置 | 右侧世界法线 | 普通 Mesh UV 的处理 |
| --- | --- | --- | --- |
| 模型与浮雕一起镜像 | $1-x$ | $-n_x(1-x)T+n_y(1-x)B+n_z(1-x)N$ | 使用匹配的网格切线链路 |
| 模型镜像，材质整体保持朝向 | $x$ | $n_x(x)T+n_y(x)B+n_z(x)N$ | UV 与 Normal X 同时补偿 |
| 仅保留镜像采样，取消方向反射（反例实验） | $1-x$ | $n_x(1-x)T+n_y(1-x)B+n_z(1-x)N$ | 保留 UV，只补偿 Normal X；改变镜像浮雕的横向坡度 |

第一种目标下，非对称浮雕的光照变化可以是正确结果。第二种目标恢复整片材质的朝向。第三种操作虽然能保持同一纹理像素的方向，却不能同时保持镜像浮雕的坡度；因此不将它列为 AI 法线的推荐修复。

### 保持浮雕朝向，需要同时恢复位置和方向

在本文的 Quad 上，负缩放改变了两件事：同一归一化位置采到了另一侧的 UV，网格切线 T 也反向了。**翻 UV 恢复采样位置；翻 Normal X 恢复方向解释。** 只完成一步，非对称浮雕通常仍然不同。

下面是 UE5.3/5.4 的 Custom 接入示例，材质保持 **Tangent Space Normal 开启**。`MirrorX` 显式传入 0/1，分别表示正常实例和本例的 X 镜像实例；可由材质实例或项目已有的实例参数提供。

第一个 Custom：输入 `UV` 为 float2、`MirrorX` 为 float，输出 float2，接 Texture Sample 的 UV。

```hlsl
float m = step(0.5, MirrorX);
return float2(lerp(UV.x, 1.0 - UV.x, m), UV.y);
```

法线 Texture Sample 使用 Normal 类型。其已解码输出接第二个 Custom：输入 `NormalTS` 为 float3、`MirrorX` 为 float，输出 float3，接材质 Normal。

```hlsl
float m = step(0.5, MirrorX);
return float3(NormalTS.x * (1.0 - 2.0 * m), NormalTS.yz);
```

需要保持朝向的 BaseColor、Roughness 等纹理使用相同的 UV 补偿。可以回到前面的交互，切换“只补偿 UV”“只补偿 Normal X”“两者同时补偿”，观察前两项分别遗漏了什么。

这段代码的适用条件是模型 X 与 U 对齐，且镜像后 B/N 保持。`1-u` 围绕 `u=0.5` 补偿，一般形式是 `2*PivotU-u`；平铺、偏移和 UV 旋转要按实际映射组织。负缩放行列式只能表明整体朝向是否反转，不能确定哪根轴为负，因此这里不把它当成通用的 `MirrorX` 自动检测。

### 为什么取消方向反射后，凹凸也可能改变

在最小平面模型中，原高度为 $H(x,v)$，镜像后的高度为 $H_m(x,v)=H(1-x,v)$。横向导数是：

$$
\frac{\partial H_m}{\partial x}=-H_u(1-x,v).
$$

高度导数决定扰动后的表面方向；[PBRT 的 Bump Mapping 推导](https://www.pbr-book.org/3ed-2018/Materials/Bump_Mapping)从位移表面的切向导数构造着色法线。这里使用前文的平面简化模型。

原法线的 X 分量对应 $-H_u$。所以真实镜像后的世界 X 分量应对应 $+H_u(1-x,v)$，也就是前面公式中的 $-n_x(1-x,v)$。若强行取消 T 反向，世界 X 分量又变回 $n_x(1-x,v)$，**它与镜像高度要求的横向坡度相反**。

这个操作不一定将整个凸起完整翻成凹坑，因为 Y 坡度通常没有同时反号；但会造成横向坡度、局部凸凹线索或光照走向变化。一般二维法线场经这种单分量改动后，还未必能对应一个连续高度场。严格对称圆顶最直观：正确镜像时仍是同一个圆顶，取消 X 方向反射反而破坏了这个结果。

因此，“对应纹理像素的方向角差为 0”只能证明方向被保留，**不能证明镜像浮雕的凹凸正确，也不能证明 AI 法线已修复**。交互中的“仅保留镜像采样，取消方向反射”保留为反例实验；请对比圆顶的默认结果及高度视图，并查看新增的“与右侧显示高度的坡度平均误差”：默认镜像和双重补偿匹配各自高度，单独取消方向反射则出现坡度误差。模拟 X 偏置仍只用于观察一个已知方向问题，不是 AI 模型质量测量。

### AI 法线不规整，先检查资产，再决定分离哪些纹理

待使用的 AI 法线可能存在方向偏置、错误凸凹、局部坡度不连续或编码问题。需要检查实际资产，不能由“AI 生成”直接判定不合格；合法的非对称浮雕也会在镜像后改变光照。**正确基底负责正确解释输入，不能补回输入中不存在的几何信息。**

如果需要可信的浮雕，优先从经过检查的高度或几何重新生成法线。镜像高度后再生成法线，会自然包含链式法则要求的方向变化；它恢复的是镜像坡度的一致性，不保证在固定世界灯光下两侧同位置亮度相同。本文已有测试图可用于先排除材质链路问题。

如果美术目标是“颜色花纹镜像，但法线细节保持原朝向”，则把 **Color UV 与 Normal UV 分开**。在本文 Quad 上，BaseColor 保留原 Mesh UV；Normal 使用上节的 `1-UV.x` 采样补偿，加上已解码 `NormalTS.x` 的方向补偿。法线场可在同位置恢复一致，颜色图案仍镜像。

这会使颜色纹样与法线细节失去逐像素对应。对于独立的细噪声可以作为风格取舍；对于叶片边缘、雕刻沟槽等对应关系明确的浮雕，错位可能更明显，应检查实际效果。若 Height、视差或位移也表达同一浮雕，不能在保留镜像 Height 的同时把 Normal 当成未镜像浮雕，并声称几何关系仍一致。

## 换成世界坐标采样后，法线应当沿哪套轴解释

上一章依赖网格 UV 与网格切线一一对应。但若材质改为世界位置投射，纹样可能已经保持了世界朝向，而网格 T 仍随负缩放反向。此时再次套用上一章的 UV 补偿，或直接把新采样结果交给旧网格 TBN，都可能产生错误。

**本章解决的是“换了采样坐标后，法线方向如何跟着换”。** 它不是另一套独立的镜像修复：前面始终讨论的“采样位置＋方向解释”，在这里仍然必须成对匹配。

| 纹理坐标来自哪里 | 贴图的 X/Y 分量代表什么方向 | 用哪套基底重建法线 |
| --- | --- | --- |
| 网格 UV | 网格 U/V 方向 | 与该 UV 匹配的网格切线基底 |
| 固定世界平面投射 | 自定义世界 U/V 方向 | 生成投射坐标的那套世界轴 |

例如在门表面上固定一套世界投射轴 `UAxisWS`、`VAxisWS`、`BaseNormalWS`。它们是与表面及贴图约定一致的正交单位基底；U/V 密度为正。采样得到 `NormalMapTS` 后，用这些轴重建世界法线：

```hlsl
return normalize(
    NormalMapTS.x * UAxisWS +
    NormalMapTS.y * VAxisWS +
    NormalMapTS.z * BaseNormalWS
);
```

这个 Custom 的输入均为 float3，输出 float3。若直接接材质 Normal，**关闭 Tangent Space Normal**；若希望沿用现有切线空间材质，则把这个世界法线经 Transform 节点转换为 Tangent 后再接 Normal。[Epic 的无切线空间 bump 示例](https://dev.epicgames.com/documentation/en-us/unreal-engine/bump-mapping-w/o-tangent-space?application_version=4.27)说明了世界法线输出的输入约定。

这里不要求把法线贴图重新烘焙成世界空间贴图。源贴图仍表达相对于纹理 U/V 的方向，只是在采样后换成正确的世界轴解释。**选择世界空间输出还是切线空间输出，不能替代这一步基底匹配。**

因此，普通 UV 已经工作的材质可以继续使用切线空间；自定义投射则先按投射基底得到正确方向，再决定输出空间。固定世界投射不必随物体一起镜像；Local Mapping 若保留或去除了缩放符号，其采样轴与重建轴也要采取一致策略。曲面、Triplanar 和非均匀缩放需要各自的基底处理，不能直接套用本例的单平面代码。

### Local Mapping：保留真实轴，避免用手性强行改方向

Local Position 与 Local Normal 决定的采样继续随物体移动；映射输出 `AxisU_LS`、`AxisV_LS`，两根轴分别做 Local→World。**法线的 X/Y 必须分别对应 UV.x/UV.y 所表达的真实方向，包括镜像后的方向。** 不把 U 额外乘以 `Handedness` 来取消镜像，也不从真实基底中去掉缩放符号。

下面为 UE5.3/5.4 的单平面正交化示例，不使用 `ddx/ddy`。`AxisU_WS`、`AxisV_WS` 已包含真实 Local→World 变换；`NormalWS` 使用几何法线，如 `VertexNormalWS`，不是已受法线贴图扰动的着色法线。输入均为 float3，输出为世界法线。

```hlsl
float3 N = normalize(NormalWS);
float3 U = AxisU_WS;
U -= N * dot(U, N);
float u2 = dot(U, U);
if (u2 < 1e-8) return N;
U *= rsqrt(u2);
float3 V = AxisV_WS;
V -= N * dot(V, N);
V -= U * dot(V, U);
float v2 = dot(V, V);
if (v2 < 1e-8) return N;
V *= rsqrt(v2);
return normalize(NormalTS.x * U + NormalTS.y * V + NormalTS.z * N);
```

`NormalTS` 接 Normal 类型采样器的已解码输出，UV 保持原映射。直接把结果接材质 Normal 时**关闭 Tangent Space Normal**；采用切线空间输出时先将结果转换回 Tangent。退化轴返回几何法线只是稳定后备，仍须修正轴输入。此代码针对可建立正交纹理基底的平面；任意曲面、UV 斜切与非均匀缩放下的真实高度坡度，还需要处理相应的表面参数尺度，正交化本身不是通用高度梯度解算。

`Handedness` 表示一套基底的定向。例如 `V=normalize(cross(N,U))*Handedness` 可用于恢复真实 V 的方向，但前提是 U/N 正交、V 应与该叉积平行，而且手性已正确提供。它不能告诉你“应该把 U 转回哪边”。只因为镜像基底是另一种手性就去改变 U，会改变法线贴图分量的几何含义。

### 和直接使用 Tangent Normal 有什么区别

两者都在把切线空间分量变成参与光照的方向，区别在于使用哪套基底。只有自定义 U/V/N 与网格 Tangent/Bitangent/Normal 一致，并且采样和通道约定也一致时，二者才等价。**procedural UV 与 Mesh UV 的轴不一致时，不能把采样法线直接交给原网格切线基底。**

因此，使用普通 Mesh UV 且网格切线匹配时，直接使用 Tangent Normal 足够。保留 Local Mapping 时，则显式使用映射对应的两根轴；选择世界法线输出是接入方式，不是修复源法线质量的算法。

### 暂不为了少一次轴变换改变实现

在前述正交与手性条件成立时，可以只变换 U，再由 N、U 和已知手性重建 V。但若手性仍需从真实 V 判断，就不能宣称省掉了那条 V 变换；若原基底包含非正交关系，也不能只靠叉积恢复。

显式矩阵乘法与三轴加权和本质上是同一种线性组合，实际指令由编译器及上下文决定。“少一次变换”也不等于已测得 GPU 收益。当前取舍是保留双轴变换，让采样轴和重建轴容易核对；本文没有 UE Shader 编译统计或 GPU 时间测量，不给出确定的 ALU 节省数字。

## 用对照测试判断：内容变了，还是法线链路错了

选好了目标和基底，才有明确的验收标准。这里的测试只回答一个问题：**当前变化是否符合所选目标，还是采样与方向解释的实现偏离了目标？**

先使用普通正交 Quad，暂时排除 WPO、双面翻转和额外法线混合。确认 Normalmap 导入、sRGB 关闭、Normal 采样器及来源的 Green 约定，然后观察世界法线，而不是只观察某一盏灯下的颜色。

### 第一步：用方向图检查网格 UV 与切线方向

普通 Mesh UV 采样四象限图，比较各象限预测的世界方向。默认 X 镜像应满足：

$$
N'_w(x,v)=R N_w(1-x,v).
$$

这里比较的是“另一侧法线再做方向反射”，并不要求左右同位置颜色相同。如果方向图就不符合预期，先检查导入、网格切线和镜像后的基底。

### 第二步：用严格对称的浮雕检查镜像抵消

将方向图换成严格对称的高度法线。此时贴图额外满足 Nx 左右反号、Ny/Nz 相同，所以正确链路应进一步满足：

$$
N'_w(x,v)\approx N_w(x,v).
$$

这一步给出了一个明确的“应当一样”样例。为避免只用球形，本文提供了包含沟槽和凸起的复杂对称测试图：

- [对称法线 PNG，512×512](/img/posts/normal-map-mirror-symmetry/symmetric-normal.png)
- [对称高度 PNG，16 位](/img/posts/normal-map-mirror-symmetry/symmetric-height-16.png)
- [生成与数学检查脚本](/img/posts/normal-map-mirror-symmetry/generate_test.py)

脚本从浮点高度函数用中心差分生成法线，并验证了单位长度、镜像对称、非对称反例及双重补偿。浮点对称场最大分量差为 0，单位长度误差小于 $10^{-12}$；PNG 量化、引擎压缩和 Mip 过滤后应按容差比较方向。U 向图片右侧、V 向下，Green 方向仍需与项目 B 轴对应；16 位高度按 `[-0.25,0.55]` 区间编码。

### 第三步：放回实际花纹，再接回自定义映射

先让实际花纹走已经检查过的普通 UV 链路，再切回项目的自定义映射。这个顺序让你每次只改变一个条件。

| 对照结果 | 下一步关注哪里 |
| --- | --- |
| 实际花纹符合理论镜像场，但同位置不一样 | 检查花纹是否严格对称，以及是否选错了验收目标 |
| 保持朝向的需求下，双重补偿恢复了一致方向 | 本文对齐平面的材质补偿达到了目标 |
| 取消方向反射后，同一像素方向保持但浮雕凹凸改变 | 检查镜像高度的坡度；撤回不匹配的轴补偿 |
| 分离 Color/Normal UV 后法线一致，但纹样与凹凸错位 | 这是分离采样的代价，不能由法线一致掩盖 |
| 普通 UV 符合预期，换自定义映射后方向错误 | 检查新 U/V 与法线重建基底是否对应 |
| 方向图或严格对称图在普通 UV 下就异常 | 先修正基本法线链路，再讨论实际花纹 |

“贴图是否合法”与“贴图是否对称”是两项不同检查。单位长度、XY 单位圆和解码方式可用于检查编码；前面的镜像关系用于检查对称性。重新归一化不会让非对称浮雕自动对称，也不能恢复错误混合丢失的细节。

上述测试覆盖的是当前网格和材质条件；项目采用 ISM、Nanite、双面或移动路径时，应在相应路径中复查同样的预期方向。

## 回到最初的问题：球形一样，浮雕不同说明了什么

居中的球形凸起满足严格镜像对称条件，采样位置交换与切线反向可以抵消。四象限图和一般浮雕不一定满足这个条件，所以镜像后不同，既不能直接证明贴图坏了，也不能直接证明 UE 的切线链路坏了。

对制作两扇门的需求，判断顺序现在就清楚了：**先确定颜色与浮雕分别要怎样镜像，再用匹配的真实基底解释法线，并同时检查方向和凹凸。** 普通 UV 下需要保持朝向时，本例同时补偿 UV 与 Normal X；改用世界投射时，按投射轴重建方向。对于不规整的 AI 法线，先检查编码与坡度质量。若颜色镜像而法线保持原朝向，可明确分离 Color/Normal UV 并检查错位代价；仅保留镜像 Normal UV、再取消方向反射，会改变镜像高度所要求的坡度，不作为通用修复。Local Mapping 保留真实两轴，暂不为了少一次变换增加手性推断。

因此，法线贴图可以镜像使用。需要处理的是艺术目标与材质坐标之间的对应关系；球形只是其中一个特殊、容易抵消变化的样例。
